# Synthetix v2: Browser Web Apps

## 결론

Synthetix v2는 여러 `.ax` 파일로 화면과 순수 로직을 작성하고, 로직을
검증한 뒤 브라우저에서 실행하는 웹앱 빌드 도구다.

WASM은 언어 자체가 아니라 검증된 로직을 실행하기 위한 기본 백엔드다.
사용자는 폴더 구조를 따로 지킬 필요가 없고, `import`가 가리키는 파일만
프로젝트 그래프에 포함된다.

## 목표

다음 명령으로 프로젝트를 시작하고 저장하면서 확인할 수 있어야 한다.

```text
axiom dev
```

이 명령은 `synthetix.toml`의 진입 파일에서 시작해 연결된 `.ax` 파일을
읽고, 검증된 WASM과 브라우저용 연결 코드를 만든 뒤 localhost에서 결과를
제공한다. 소스 파일을 저장하면 다시 컴파일하고 브라우저를 새로고침한다.

## 프로젝트 설정

설정 파일의 이름은 `synthetix.toml`이다.

```toml
[project]
entry = "main.ax"
target = "web"
storage_schema_version = 1
```

- `entry`: 컴파일을 시작할 파일. 파일명과 폴더 위치는 사용자가 정한다.
- `target`: 출력 환경. v2의 기본값은 `web`이다.
- `storage_schema_version`: `persist` 상태 저장 형식의 버전. 생략하면 `1`이며,
  저장 상태 구조를 바꾸면 값을 올리고 application migration을 제공한다.

`axiom build path/to/file.ax`는 작은 예제를 위한 단일 파일 모드로 계속
지원한다. `axiom build`와 `axiom dev`는 설정 파일을 읽는다.

## 모듈

파일 간 연결은 명시적인 `import`와 `export`로만 만든다.

```axiom
// math.ax
export contract add(x: u32, y: u32) -> u32 {
    ensures result == x +% y;
}
```

```axiom
// main.ax
import { add } from "./math.ax";

contract total(x: u32, y: u32) -> u32 {
    ensures result == add(x, y);
}
```

컴파일러는 `main.ax`에서 시작해 상대 경로 import를 해석하고, 연결된
모듈의 계약 호출을 하나의 검증 그래프로 합친다. 사용하지 않은 `.ax`
파일은 자동으로 포함하지 않는다.

모듈 규칙:

- 경로는 import한 파일을 기준으로 해석한다.
- export되지 않은 계약은 다른 모듈에서 사용할 수 없다.
- 같은 이름을 중복 export하면 오류다.
- 순환 import는 컴파일 오류다.
- 오류에는 원본 파일과 줄 번호를 포함한다.

## 웹 출력

```text
dist/
├── index.html
├── app.js
├── app.wasm
├── app.css
└── app.proof.json
```

- `index.html`: 웹 진입 페이지
- `app.js`: 브라우저에서 WASM을 불러오고 계약을 호출하는 연결 코드
- `app.wasm`: Z3 검증을 통과한 순수 로직
- `app.css`: 생성되는 기본 스타일
- `app.proof.json`: 어떤 계약이 검증됐는지 기록

웹 출력은 정적 파일이다. 빌드가 끝난 뒤에는 Synthetix나 Z3 없이도
정적 호스팅에서 실행할 수 있어야 한다.

## 개발 명령

```bash
axiom dev       # 빌드 + localhost 서버 + 저장 시 자동 새로고침
axiom build     # 배포용 정적 파일 생성
axiom check     # 파싱·타입·검증만 수행
```

v2의 첫 개발 서버는 HMR이 아니라 Live Reload를 사용한다. 저장하면 현재
페이지를 다시 불러온다. 입력값과 화면 상태를 유지하는 HMR은 이후 범위다.

`axiom dev`가 시작하는 localhost 서버는 로그인·DB·API를 처리하는
백엔드가 아니다. 브라우저에 개발 중인 정적 파일을 전달하기 위한 서버다.

## 검증 경계

Z3가 검증하는 대상:

- 순수 계약 함수
- 숫자·불리언 계산
- 조건식과 입력 조건
- 모듈 간 계약 호출
- 제한된 데이터 변환

v2가 자동으로 증명하지 않는 대상:

- HTML/CSS의 시각 결과
- 브라우저의 DOM 동작
- 네트워크·DB·로그인·결제
- 서버 코드

웹 UI는 생성하고, 중요한 계산·검증 규칙은 계약으로 작성해 증명한다.
검증에 실패하면 배포용 웹 산출물을 만들지 않는다.

## 범위에서 제외

v2에서는 다음을 만들지 않는다.

- 백엔드 서버와 데이터베이스
- 사용자 인증과 결제
- 서버 사이드 렌더링
- native 실행 파일 백엔드
- 패키지 매니저와 폴더 구조 규칙
- 상태를 보존하는 완전한 HMR
- 무한 루프와 무제한 메모리

## 완료 기준

다음 흐름이 실제로 동작하면 v2의 첫 완성으로 본다.

1. 임의의 위치에 있는 `main.ax`가 `import`한 다른 `.ax` 계약을 호출한다.
2. `axiom dev`가 브라우저를 열고 검증된 결과를 실행한다.
3. `.ax` 파일을 저장하면 다시 컴파일되고 브라우저가 갱신된다.
4. 잘못된 계약은 파일명과 줄 번호가 포함된 오류를 낸다.
5. `axiom build`가 브라우저에서 직접 열 수 있는 정적 출력물을 만든다.
6. 카운터 예제가 화면·이벤트·검증된 로직을 모두 보여준다.
