# Synthetix v3: Verified Application Language

## 한 문장 목표

Synthetix v3는 사용자가 JavaScript 구현 코드를 직접 작성하지 않고
`.ax` 파일로 데이터·상태·화면·이벤트를 정의하면, 순수한 상태 변경 로직을
검증한 뒤 웹앱으로 실행하는 애플리케이션 언어다.

```text
.ax 명세
  → 타입 검사
  → 함수 연결
  → Z3 검증
  → WASM 생성
  → 상태 기반 웹 UI 실행
```

## v3의 경계

검증하는 것:

- `u32`와 `bool`의 순수 계산
- 함수의 입력·출력 타입
- 계약 호출과 `requires` / `ensures`
- 상태 변경 함수의 결과
- 조건부 화면에 사용되는 순수 값

아직 검증하지 않는 것:

- DOM과 CSS의 시각 결과
- 네트워크·DB·로그인
- 선언되지 않은 브라우저 외부 효과 (`persist` localStorage만 예외)
- 무제한 재귀와 무한 반복
- 임의의 JavaScript 코드

## v3.0 구현 범위

이번 버전은 기존 v2를 깨지 않는 타입·상태 확장이다.

### 타입

```axiom
program is_ready(value: number) -> bool {
    gives answer equals value > 0;
}
```

`number`는 기존 `u32`와 같은 WebAssembly `i32` 비트벡터 의미를 유지한다.
`bool`은 `true` 또는 `false`이며 WASM ABI에서는 `0` 또는 `1`로 표현한다.

### 상태와 조건부 화면

```axiom
page Counter {
    state count: number = 0;
    state ready: bool = false;

    show count;
    when ready show "준비됨";
    button "더하기" updates count with increment(count);
}
```

`when`은 순수 불리언 상태를 조건으로 화면 요소를 표시한다. DOM 결과 자체는
검증 대상이 아니지만, 조건 계산과 상태 변경 함수는 검증한다.

화면에 고정된 안내 문구를 표시할 때는 `show "문구";`를 사용한다.

### 여러 상태를 가진 이벤트

v3.0에서는 한 버튼이 한 상태를 갱신하는 기존 문법을 유지한다. 여러 상태를
한 번에 바꾸는 reducer 형태는 v3.1에서 추가한다.

### 예제

- `examples/v3-status`: `bool` 계약과 조건부 상태 메시지
- `examples/v3-todo`: 여러 불리언 상태를 사용하는 상태 기반 체크리스트

`v3-todo`는 고정된 항목을 다루는 첫 상태 앱이다. 동적 `list<Todo>`와
입력창은 v3.1에서 추가한다.

## v3.1 구현 범위

v3.1은 순수 계약의 검증 경계를 유지하면서 웹 화면의 데이터 모델과 상태
효과를 확장한다.

```axiom
record Todo {
    title: text;
    done: bool;
}

page Todo {
    state todos: list<Todo> = [];
    state draft: text = "";
    persist todos;

    input draft placeholder "할 일을 입력하세요";
    button "추가" adds todos with Todo { title: draft, done: false };
    list todos as todo {
        show todo.title;
        when todo.done show "완료됨";
    }
}
```

- `record`, `list`, `text`: 화면 데이터 전용 타입
- `input`: `text` 상태와 연결되는 입력창
- `list ... as ...`: 목록과 항목별 화면·이벤트
- `reducer`: 검증된 scalar contract 여러 개를 묶어 여러 상태를 갱신
- `persist`: 지정한 상태만 `localStorage`에 저장하는 명시적 외부 효과
- `component`와 `use`: 재사용 가능한 정적 화면 조각
- VSCode hover, 기본 formatter, v3.1 문법 자동완성

`record/list/text` 자체는 Z3/WASM 계약 타입이 아니다. 브라우저 데이터와
DOM 경계에만 존재하며, 목록 항목의 `done` 변경처럼 계산이 필요한 부분은
`bool`/`number` 계약을 호출해서 검증된 WASM 결과만 반영한다.

## 완료 기준

v3.0은 다음이 모두 동작하면 완료로 본다.

1. `bool` 계약이 파싱·타입 검사된다.
2. `bool` 계약이 Z3 검증을 통과하고 WASM으로 생성된다.
3. 여러 `.ax` 파일의 함수 호출이 타입을 보존한다.
4. 페이지에서 조건부 요소가 상태에 따라 보인다.
5. 잘못된 타입과 잘못된 조건은 파일·줄 정보와 함께 실패한다.
6. 기존 v1/v2 예제와 CLI 명령이 계속 동작한다.

v3.1은 다음을 추가로 확인하면 완료로 본다.

1. record/list/text 상태가 파싱·타입 검사·웹 bundle 생성까지 연결된다.
2. 입력창으로 text 상태를 바꾸고 list에 record를 추가할 수 있다.
3. 목록 항목의 bool 상태를 검증된 계약으로 바꿀 수 있다.
4. reducer가 여러 검증된 계약을 순서대로 실행한다.
5. persist 상태가 새로고침 뒤에도 유지되고, 비 persist 상태는 초기화된다.
6. component/use, VSCode hover/formatter/completion이 동작한다.

## 설계 원칙

- 문법은 쉬운 단어를 우선한다.
- 검증되지 않은 순수 로직은 WASM으로 방출하지 않는다.
- UI 생성 코드와 증명 대상인 순수 로직을 분리한다.
- 기능을 늘릴 때마다 합성 범위와 증명 범위를 명시한다.
- Python의 기능 수나 코드 줄 수를 목표로 삼지 않는다.
